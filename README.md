# Концепти для Порталу послуг «Київ Цифровий»

Продуктові концепти для [Порталу послуг Києва](https://portal.kyiv.digital/). Кожен концепт — це самодостатня HTML-сторінка (презентація) плюс детальний документ у Markdown, за яким можна писати технічне завдання.

**Робочі документи для обговорення, не офіційна позиція міста.**

## Що всередині

Кожен концепт живе в окремій теці: `index.html` — презентація, `concept.md` — повний документ. Перелік концептів навмисно не наводиться тут — він у каталозі на головній сторінці сайту, під паролем.

## Структура

```
.
├── index.html          каталог під паролем (генерується, не редагувати вручну)
├── _catalog.html       вміст каталогу — ЛОКАЛЬНИЙ, у репозиторій не потрапляє
├── .password.txt       пароль — ЛОКАЛЬНИЙ
├── tools/
│   ├── lock.mjs             збирає index.html із _catalog.html
│   └── gate.template.html   сторінка-замок
├── gamification/
│   ├── index.html      презентація
│   └── concept.md      повний документ
└── osvita/
    ├── index.html      презентація
    └── concept.md      повний документ
```

## Каталог під паролем

Головна сторінка захищена: її вміст лежить у файлі як шифротекст **AES-256-GCM**, ключ виводиться з пароля через **PBKDF2-HMAC-SHA256, 310 000 ітерацій**, просто в браузері відвідувача. Пароль нікуди не надсилається, а без нього в сторінці нема чого читати.

**Самі концепти паролем не закриті** — прямі посилання на `gamification/` та `osvita/` відкриваються без нього.

Щоб змінити вміст каталогу або пароль:

```bash
# 1. відредагувати вміст
open _catalog.html

# 2. перезібрати сторінку (пароль можна той самий або новий)
node tools/lock.mjs "новий-пароль"

# 3. запушити
git add index.html && git commit -m "Оновлено каталог" && git push
```

Файли `_catalog.html` і `.password.txt` навмисно в `.gitignore` — плейнтекст каталогу не має потрапляти в публічний репозиторій. **Тримайте їхню копію в безпечному місці:** без `_catalog.html` каталог доведеться складати заново.

### Межі цього захисту

Це статичний хостинг без сервера, тому захист має стелю, і про неї варто знати:

- Шифротекст лежить у публічному файлі, тож пароль можна підбирати офлайн. 310 000 ітерацій PBKDF2 роблять перебір повільним, але не неможливим — не використовуйте короткий чи словниковий пароль.
- Репозиторій публічний: теки `gamification/` і `osvita/` видно на GitHub, навіть якщо каталог зашифрований. Щоб закрити й це, потрібен приватний репозиторій (Pages з приватного репо працює на GitHub Pro) або переїзд на Cloudflare Pages зі справжньою серверною перевіркою пароля.
- Мета цього замка — щоб посилання, яке «пішло по руках», не показувало загальний список концептів. Для захисту справді чутливих даних цього недостатньо.

## Як додати новий концепт

1. Створити теку з латинською назвою в нижньому регістрі, наприклад `transport/`.
2. Покласти туди `index.html` (презентація) і `concept.md` (документ).
3. Додати картку концепту в `_catalog.html` — скопіювати блок `<a class="deck">` і замінити текст.
4. Перезібрати каталог: `node tools/lock.mjs "пароль"`.
5. Додати рядок у таблицю вище.
6. Закомітити й запушити — GitHub Pages оновиться сам за хвилину-дві.

**Не забудьте** додати `<meta name="robots" content="noindex, nofollow">` у новий `index.html`: `robots.txt` у підпапці проєктного сайту пошуковики не читають, працює лише цей тег на самій сторінці.

## Технічні деталі

- Палітра всіх сторінок узята з чинних стилів Порталу послуг: `#0069ff` синій, `#f1f7ff` підложка, `#1d1d1f` текст, `#878383` вторинний, `#e5e5ea` лінії.
- Файл `.nojekyll` вимикає обробку Jekyll — сторінки віддаються як є.
- Сторінки адаптивні й працюють без JavaScript-фреймворків. Кожна презентація — один самодостатній HTML-файл без збірки й залежностей; зовні підвантажуються тільки шрифти Google Fonts.
